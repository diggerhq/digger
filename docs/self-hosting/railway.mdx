## Deploy with the Railway template

<Steps>
  <Step title="Start from the OpenTaco Railway template">
    [![Deploy on Railway](https://railway.com/button.svg)](https://railway.com/deploy/FIg15a)
  </Step>
  <Step title="Set pre-deploy variables">
    During template setup, add your WorkOS values to the UI service (see [WorkOS Setup](./workos-setup)) and set `GITHUB_ORG` in the orchestrator service before the initial deploy.
  </Step>
  <Step title="Provision the project and services">
    Let Railway create the project and provision all services in the canvas.
  </Step>
  <Step title="Configure a public domain">
    After provisioning, either generate a Railway public domain for the UI service or configure your own custom domain using Railway's CNAME flow.
  </Step>
  <Step title="Set remaining required environment variables">
    Open each service in Railway and set the required environment variables using [Configuration](./configuration).
  </Step>
  <Step title="Redeploy and verify access">
    Redeploy affected services after updating variables, then confirm the app is reachable through your configured domain.
  </Step>
  <Step title="Set up the GitHub App">
    After access is verified, complete the [GitHub App setup flow](/onboarding/github-app-setup).
  </Step>
</Steps>

Verify platform functionality such as:

- Terraform/Opentaco backends via `units`
- `remote runs` (if configured and enabled)
- PR automation workflows
- Drift detection and notifications
