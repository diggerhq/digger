---
title: "digger.yml"
description: "Reference for configuring Digger via the digger.yml configuration file"
---

<Note>
  Fields marked as **Required** must be set. Optional fields have sensible defaults shown below.
</Note>

You can configure Digger by dropping a `digger.yml` file at the root level of your repo.

```yml
projects:
  - name: my-first-app
    dir: app-one
  - name: my-second-app
    dir: app-two
auto_merge: true
```

You can also name your Digger configuration file differently, and specify its name using the `digger-filename` input at GitHub Action level.

## Top-level Configuration

<ParamField path="telemetry" type="boolean" default="true">
  Allows collecting anonymised usage and debugging data.
</ParamField>

<ParamField path="auto_merge" type="boolean" default="false">
  Automatically merge pull requests when all checks pass.
</ParamField>

<ParamField path="auto_merge_strategy" type="string" default="squash">
  The merge strategy to use while automerging. Possible values: `squash`, `merge` (for merge commits), and `rebase`. Currently only GitHub supported.
</ParamField>

<ParamField path="pr_locks" type="boolean" default="true">
  Enable PR-level locking to prevent concurrent operations on the same project.
</ParamField>

<ParamField path="delete_prior_comments" type="boolean" default="false">
  Enables Digger to delete previous comments to reduce noise in the PR.
</ParamField>

<ParamField path="traverse_to_nested_projects" type="boolean" default="false">
  Enable traversal of nested directories to discover projects.
</ParamField>

<ParamField path="allow_draft_prs" type="boolean" default="false">
  Allow Digger to run on draft pull requests.
</ParamField>

<ParamField path="apply_after_merge" type="boolean" default="false">
  Automatically run apply after a pull request is merged.
</ParamField>

<ParamField path="respect_layers" type="boolean" default="false">
  Respect project layers when determining execution order. See [layering](/ce/features/layering) for details.
</ParamField>

<ParamField path="disable_digger_apply_comment" type="boolean" default="false">
  Disable the `digger apply` comment prompt after successful plan.
</ParamField>

<ParamField path="disable_digger_apply_status_check" type="boolean" default="false">
  Disable the status check that verifies apply was executed.
</ParamField>

<ParamField path="comment_render_mode" type="string" default="basic">
  How to render plan output in comments. Options: `basic`, `detailed`.
</ParamField>

<ParamField path="mention_drifted_projects_in_pr" type="boolean" default="false">
  Mention projects that have drifted from the target state in PR comments.
</ParamField>

<ParamField path="report_terraform_outputs" type="boolean" default="true">
  Include Terraform outputs in the PR comment after apply.
</ParamField>

<ParamField path="projects" type="array">
  List of projects to manage. See [Project Configuration](#project-configuration).
</ParamField>

<ParamField path="generate_projects" type="object">
  Generate projects from a directory structure. See [GenerateProjects Configuration](#generateprojects-configuration).
</ParamField>

<ParamField path="workflows" type="map">
  Workflows and configurations to run on events. See [Workflow Configuration](#workflow-configuration).
</ParamField>

<ParamField path="reporting.ai_summary" type="boolean" default="false">
  Enable AI-generated summaries of plan output. See [AI Summaries](/ce/features/ai-summaries).
</ParamField>

<ParamField path="reporting.comments_enabled" type="boolean" default="true">
  Enable posting plan/apply results as PR comments.
</ParamField>

<ParamField path="dependency_configuration.mode" type="string" default="hard">
  Dependency execution mode: `hard` executes dependency projects even if unchanged, `soft` skips them if unchanged.
</ParamField>

## Project Configuration

Define individual projects using the `projects` array.

<ParamField path="name" type="string" required>
  Name of the project. Must be unique across all projects.
</ParamField>

<ParamField path="dir" type="string" required>
  Directory containing the Terraform/OpenTofu/Terragrunt code, relative to the repository root.
</ParamField>

<ParamField path="branch" type="string">
  The target branch to match this project on. Defaults to the repository's default branch when not set.
</ParamField>

<ParamField path="alias" type="string">
  An alternative name for the project, useful for referencing in commands.
</ParamField>

<ParamField path="apply_requirements" type="array" default='["mergeable"]'>
  List of requirements that must be met before apply can run. Options: `approved`, `mergeable`, `undiverged`. See [apply requirements](/ce/howto/apply-requirements) for details.
</ParamField>

<ParamField path="workspace" type="string" default="default">
  Terraform workspace to use for this project.
</ParamField>

<ParamField path="terragrunt" type="boolean" default="false">
  Whether to use Terragrunt for this project.
</ParamField>

<ParamField path="opentofu" type="boolean" default="false">
  Whether to use OpenTofu instead of Terraform.
</ParamField>

<ParamField path="pulumi" type="boolean" default="false">
  Whether to use Pulumi for this project.
</ParamField>

<ParamField path="pulumi_stack" type="string">
  The Pulumi stack to use when `pulumi: true`.
</ParamField>

<ParamField path="workflow" type="string" default="default">
  Name of the workflow to use for this project.
</ParamField>

<ParamField path="workflow_file" type="string" default="digger_workflow.yml">
  Name of the GitHub Actions workflow file for this project.
</ParamField>

<ParamField path="drift_detection" type="boolean" default="true">
  Enable drift detection for this project. See [Drift Detection](/onboarding/drift-detection-remediation).
</ParamField>

<ParamField path="layer" type="number" default="0">
  Layer number for controlling execution order when `respect_layers` is enabled. Lower layers execute first.
</ParamField>

<ParamField path="include_patterns" type="array" default="[]">
  List of directory glob patterns to include as dependencies, e.g., `["../modules/**"]`. See [Include / Exclude Patterns](/ce/howto/include-exclude-patterns).
</ParamField>

<ParamField path="exclude_patterns" type="array" default="[]">
  List of directory glob patterns to exclude, e.g., `[".terraform/**"]`. See [Include / Exclude Patterns](/ce/howto/include-exclude-patterns).
</ParamField>

<ParamField path="depends_on" type="array" default="[]">
  List of project names that must complete before this project. Does not force terraform run, but affects the order of commands for projects modified in the current PR.
</ParamField>

<AccordionGroup>
  <Accordion title="AWS Role Configuration">
    Configure AWS role assumption using the `aws_role_to_assume` key.

    <ParamField path="aws_role_to_assume.aws_role_region" type="string" default="us-east-1">
      AWS region used when performing STS web identity calls.
    </ParamField>

    <ParamField path="aws_role_to_assume.state" type="string">
      ARN of the IAM role to assume for state backend operations. If only `state` is set, it will also be used for commands.
    </ParamField>

    <ParamField path="aws_role_to_assume.command" type="string">
      ARN of the IAM role to assume for Terraform commands (plan/apply). If only `command` is set, it will also be used for state.
    </ParamField>
  </Accordion>

  <Accordion title="AWS Cognito OIDC Configuration">
    Configure AWS Cognito OIDC authentication using the `aws_cognito_oidc` key.

    <ParamField path="aws_cognito_oidc.aws_account_id" type="string" required>
      The AWS account ID where the Cognito Identity Pool is located.
    </ParamField>

    <ParamField path="aws_cognito_oidc.aws_region" type="string">
      The AWS region for the Cognito Identity Pool.
    </ParamField>

    <ParamField path="aws_cognito_oidc.cognito_identity_pool_id" type="string" required>
      The Cognito Identity Pool ID for federated authentication.
    </ParamField>

    <ParamField path="aws_cognito_oidc.session_duration" type="number">
      Session duration in seconds for the assumed role credentials.
    </ParamField>
  </Accordion>
</AccordionGroup>

## GenerateProjects Configuration

Automatically generate projects from directory structure using the `generate_projects` key.

<ParamField path="include" type="string">
  Glob pattern to include directories for project generation.
</ParamField>

<ParamField path="exclude" type="string">
  Glob pattern to exclude directories from project generation.
</ParamField>

<ParamField path="terragrunt" type="boolean" default="false">
  Whether to use Terragrunt for generated projects.
</ParamField>

<ParamField path="blocks" type="array">
  List of blocks for more granular project generation. See [Block Configuration](#block-configuration).
</ParamField>

<ParamField path="terragrunt_parsing" type="object">
  Terragrunt-specific parsing configuration. See [Terragrunt Parsing](/ce/reference/terragrunt-parsing) for all options.
</ParamField>

<ParamField path="drift_include_patterns" type="array" default="[]">
  Glob patterns matched against each project's `dir`. Only matching projects run drift detection. If empty, all projects are included. See [Backendless: Scope Drift to Specific Projects](/ce/drift/backendless-scoping-projects).
</ParamField>

<ParamField path="drift_exclude_patterns" type="array" default="[]">
  Glob patterns matched against each project's `dir`. Matching projects are skipped during drift detection. Evaluated after `drift_include_patterns`.
</ParamField>

<ParamField path="aws_role_to_assume" type="object">
  Default AWS role configuration for all generated projects. See [AWS Role Configuration](#aws-role-configuration).
</ParamField>

<ParamField path="aws_cognito_oidc" type="object">
  Default AWS Cognito OIDC configuration for all generated projects. See [AWS Cognito OIDC Configuration](#aws-cognito-oidc-configuration).
</ParamField>

<AccordionGroup>
  <Accordion title="Block Configuration">
    Blocks allow you to define multiple project generation rules with different settings.

    <ParamField path="block_name" type="string">
      Name of the block for identification.
    </ParamField>

    <ParamField path="include" type="string">
      Glob pattern to include directories. Only for Terraform and OpenTofu.
    </ParamField>

    <ParamField path="exclude" type="string">
      Glob pattern to exclude directories. Only for Terraform and OpenTofu.
    </ParamField>

    <ParamField path="include_patterns" type="array" default="[]">
      List of directory glob patterns to include as dependencies for generated projects.
    </ParamField>

    <ParamField path="exclude_patterns" type="array" default="[]">
      List of directory glob patterns to exclude from generated projects.
    </ParamField>

    <ParamField path="workflow" type="string" default="default">
      Workflow to use for projects in this block.
    </ParamField>

    <ParamField path="workflow_file" type="string">
      Name of the GitHub Actions workflow file for projects in this block.
    </ParamField>

    <ParamField path="workspace" type="string">
      Terraform workspace to use for projects in this block.
    </ParamField>

    <ParamField path="terragrunt" type="boolean" default="false">
      Whether to use Terragrunt for projects in this block.
    </ParamField>

    <ParamField path="root_dir" type="string">
      Root directory for Terragrunt projects. Only for Terragrunt.
    </ParamField>

    <ParamField path="opentofu" type="boolean" default="false">
      Whether to use OpenTofu for projects in this block.
    </ParamField>

    <ParamField path="terragrunt_parsing" type="object">
      Terragrunt-specific parsing configuration for this block. See [Terragrunt Parsing](/ce/reference/terragrunt-parsing).
    </ParamField>

    <ParamField path="aws_role_to_assume" type="object">
      AWS role configuration for projects in this block.
    </ParamField>

    <ParamField path="aws_cognito_oidc" type="object">
      AWS Cognito OIDC configuration for projects in this block.
    </ParamField>
  </Accordion>
</AccordionGroup>

## Workflow Configuration

Define custom workflows using the `workflows` map. Each workflow can have its own environment variables, plan/apply stages, and event configurations.

<ParamField path="env_vars" type="object">
  Environment variables to set per stage. See [EnvVars Configuration](#envvars-configuration).
</ParamField>

<ParamField path="plan" type="object">
  Plan stage configuration. See [Stage Configuration](#stage-configuration).
</ParamField>

<ParamField path="apply" type="object">
  Apply stage configuration. See [Stage Configuration](#stage-configuration).
</ParamField>

<ParamField path="workflow_configuration" type="object">
  Describes how to react to CI events. See [WorkflowConfiguration](#workflowconfiguration).
</ParamField>

<AccordionGroup>
  <Accordion title="EnvVars Configuration">
    Configure environment variables for different stages using the `env_vars` key.

    <ParamField path="env_vars.state" type="array" default="[]">
      Environment variables to set for terraform init stage. Useful for setting different credentials for remote backend.
    </ParamField>

    <ParamField path="env_vars.commands" type="array" default="[]">
      Environment variables to set for other terraform commands. Useful for setting different credentials for managed infrastructure.
    </ParamField>

    Each environment variable object has:

    <ParamField path="name" type="string" required>
      Name of the environment variable to set.
    </ParamField>

    <ParamField path="value" type="string">
      Direct value for the environment variable. Takes preference over `value_from` if both are set.
    </ParamField>

    <ParamField path="value_from" type="string">
      Name of another environment variable to get the value from. Useful for secrets—set a secret from a secret manager (e.g., GitHub secrets) as an environment variable, then remap it to another variable.
    </ParamField>
  </Accordion>

  <Accordion title="Stage Configuration (plan/apply)">
    Configure plan and apply stages.

    <ParamField path="filter_regex" type="string">
      Regular expression to mask sensitive values from plan output and PR comments. Matches are replaced with `<REDACTED>`. See [Masking sensitive values](/ce/howto/masking-sensitive-values).
    </ParamField>

    <ParamField path="steps" type="array" default="[]">
      List of steps to run during this stage. See [Step Configuration](#step-configuration).
    </ParamField>
  </Accordion>

  <Accordion title="Step Configuration">
    Steps can be terraform commands or custom shell commands.

    **Terraform commands** (`init`, `plan`, `apply`):
    ```yaml
    steps:
      - init
      - plan
      - apply
    ```

    **With extra arguments:**
    ```yaml
    steps:
      - init:
          extra_args: ["-backend-config=backend.hcl"]
      - plan:
          extra_args: ["-var-file=prod.tfvars"]
      - apply:
          extra_args: ["-compact-warnings"]
    ```

    **Custom shell commands:**
    ```yaml
    steps:
      - run: "echo hello world"
      - run: "checkov -d ."
        shell: zsh
    ```

    <ParamField path="init" type="string | object">
      Terraform init step. Can be a string `init` or an object with `extra_args`.
    </ParamField>

    <ParamField path="plan" type="string | object">
      Terraform plan step. Can be a string `plan` or an object with `extra_args`.
    </ParamField>

    <ParamField path="apply" type="string | object">
      Terraform apply step. Can be a string `apply` or an object with `extra_args`.
    </ParamField>

    <ParamField path="run" type="string">
      Shell command to run.
    </ParamField>

    <ParamField path="shell" type="string">
      Shell to use for the run command (e.g., `bash`, `zsh`).
    </ParamField>

    <ParamField path="extra_args" type="array" default="[]">
      Extra arguments to pass to terraform init/plan/apply.
    </ParamField>
  </Accordion>

  <Accordion title="WorkflowConfiguration">
    Configure how the workflow responds to CI events.

    <ParamField path="on_pull_request_pushed" type="array" default='["digger plan"]'>
      Commands to run when a pull request is created or updated. Options: `digger plan`, `digger apply`, `digger lock`, `digger unlock`.
    </ParamField>

    <ParamField path="on_pull_request_closed" type="array" default='["digger unlock"]'>
      Commands to run when a pull request is closed.
    </ParamField>

    <ParamField path="on_pull_request_to_draft" type="array" default="[]">
      Commands to run when a pull request is converted to draft.
    </ParamField>

    <ParamField path="on_commit_to_default" type="array" default='["digger unlock"]'>
      Commands to run when a commit is pushed to the default branch.
    </ParamField>

    <ParamField path="skip_merge_check" type="boolean" default="false">
      Allow this workflow to skip mergeability checks and run digger commands.
    </ParamField>
  </Accordion>
</AccordionGroup>

## Default Workflow

A default workflow is created automatically if you don't specify any workflows in the configuration:

```yml
workflow_configuration:
  on_pull_request_pushed: [digger plan]
  on_pull_request_closed: [digger unlock]
  on_commit_to_default: [digger unlock]
plan:
  steps:
    - init
    - plan
apply:
  steps:
    - init
    - apply
```

## Workflow Configuration Explanation

Workflow configuration describes how to react to CI events. It has 4 sections:

- **on_pull_request_pushed** - describes what to do when a pull request is created or updated
- **on_pull_request_closed** - describes what to do when a pull request is closed
- **on_pull_request_to_draft** - describes what to do when a pull request is converted to draft
- **on_commit_to_default** - describes what to do when a pull request is merged into the default branch

## Projects

A project in Digger corresponds to a directory containing Terraform code. Projects are treated as standalone independent entities with their own locks. Digger will not prevent you from running plan and apply in different projects simultaneously.

You can run plan / apply in a specified project by using the `-p` option in a GitHub PR comment:

```bash
digger apply -p my-second-app
```
