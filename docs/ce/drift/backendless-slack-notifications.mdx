---
title: "Backendless: Slack Notifications"
description: "Send backendless drift detection results to Slack from scheduled GitHub Actions runs"
---

In Backendless mode, drift detection runs in GitHub Actions and sends notifications directly from the workflow run.

## Configure Slack webhook input

Create an [incoming webhook](https://api.slack.com/messaging/webhooks) for your Slack workspace, save its URL as a repository secret named `SLACK_WEBHOOK_URL` (Settings > Secrets and variables > Actions), then pass `drift-detection-slack-notification-url` to the action:

```yml
name: Drift Detection

on:
  workflow_dispatch:
  # schedule:
  #   - cron: "0 0 * * *"

jobs:
  detect-drift:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0 # required for last change attribution
      - name: digger drift detection
        uses: diggerhq/digger@vLatest
        with:
          mode: drift-detection
          no-backend: true
          configure-checkout: false # keep the full-history checkout above
          drift-detection-slack-notification-url: ${{ secrets.SLACK_WEBHOOK_URL }}
        env:
          GITHUB_CONTEXT: ${{ toJson(github) }}
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

Each drifted project produces one compact summary message — project, repository, and who last changed it. The Terraform plan itself is never posted to the channel; find it in the workflow logs, or use [threaded plans](#threaded-plans) to post it in the message's thread.

## Last change attribution

When drift is detected, the notification includes who last changed the project's directory, taken from `git log` on the runner:

> **Last change by:** Jane Doe (`abc1234`, 3 days ago)

This requires full git history in the checkout — set `fetch-depth: 0` on `actions/checkout` **and** `configure-checkout: false` on the digger step, as shown above. Without `configure-checkout: false` the action performs its own shallow checkout, which discards the history you just fetched. On a shallow clone the attribution line is skipped and the notification is sent without it.

## Threaded plans

To see the plan in Slack without adding channel noise, use a Slack bot token instead of a webhook — the channel still gets only the summary message, and the plan (up to 40,000 characters, split into ~4,000-character replies) goes into its thread:

```yml
      - name: digger drift detection
        uses: diggerhq/digger@vLatest
        with:
          mode: drift-detection
          no-backend: true
          configure-checkout: false
          drift-detection-slack-bot-token: ${{ secrets.SLACK_BOT_TOKEN }}
          drift-detection-slack-channel: "C0123456789"
        env:
          GITHUB_CONTEXT: ${{ toJson(github) }}
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

To use this mode:

1. Create a Slack app at [api.slack.com/apps](https://api.slack.com/apps) and add the `chat:write` bot scope under OAuth & Permissions.
2. Install the app to your workspace and copy the bot token (`xoxb-...`) into a repository secret named `SLACK_BOT_TOKEN`.
3. Invite the bot to the target channel (`/invite @your-app`).
4. Pass the channel ID, not the channel name — find it at the bottom of the channel's details modal.

Both `drift-detection-slack-bot-token` and `drift-detection-slack-channel` must be set for threaded mode; if a webhook URL is configured alongside them, threaded mode takes precedence.

Plans that exceed the limit are cut at a line boundary with a note saying how many characters were omitted; the full plan is always available in the workflow logs regardless of mode.
