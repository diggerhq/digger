---
title: "Backendless: Scope Drift to Specific Projects"
description: "Scope backendless drift checks to selected projects using dedicated config file or patterns"
---




In Backendless mode, digger provides two means scoping drift detection. 



## Using dedicated config 

- Create a dedicated `digger.yml` that lists only the projects or blocks you want scanned.
- Point your drift workflow to that file using the `digger-filename` input.
- Repeat per environment if needed.

## Examples

### Explicit projects

```yml
# digger-drift-dev.yml
projects:
  - name: app-dev-a
    dir: terraform/aws_devel/app-a
    workflow: default
  - name: app-dev-b
    dir: terraform/aws_devel/app-b
    workflow: default
```

### Terragrunt-generated blocks

```yml
# digger-drift-dev.yml
generate_projects:
  blocks:
    - block_name: aws_devel
      terragrunt: true
      root_dir: terraform/aws_devel/
      workflow: default
```

## Referencing the file in your workflow

```yml
name: Drift (dev)

on:
  workflow_dispatch:

jobs:
  detect-drift:
    runs-on: ubuntu-latest
    steps:
      - uses: diggerhq/digger@vLatest
        with:
          mode: drift-detection
          no-backend: true
          digger-filename: digger-drift-dev.yml
```

## Using drift patterns

Add `drift_include_patterns` and `drift_exclude_patterns` under `generate_projects` in your main `digger.yml`:

```yaml
generate_projects:
  blocks:
    - block_name: infra
      root_dir: "infra/"
      workflow: default
      include: "**"
  drift_include_patterns:
    - "infra/prod/**"
    - "infra/staging/**"
  drift_exclude_patterns:
    - "infra/_global/**"
```

Only projects whose `dir` matches an include pattern and does not match an exclude pattern  will run drift detection. Exclude patterns are evaluated after include patterns.

## Using per-block drift patterns

You can also place `drift_include_patterns` and `drift_exclude_patterns` **inside a block**. They apply only to projects generated by that block and are matched against each project's `dir`.

```yaml
generate_projects:
  blocks:
    - block_name: crdb
      workflow: default
      include: "projects/CRDB/**"
      drift_exclude_patterns:
        - "projects/CRDB/aws/dev/staging/us-east-1/ec2/**"
    - block_name: dev
      workflow: default
      include: "infra/dev/**"
```

Here, every project generated from the `crdb` block whose directory matches `projects/CRDB/aws/dev/staging/us-east-1/ec2/**` is skipped during drift detection, while everything else in the block runs as usual. The `dev` block is unaffected.

Per-block patterns and top-level patterns compose: a project must pass both checks to run drift detection.

## Limiting Terragrunt concurrency

For large Terragrunt estates, an unbounded run can overwhelm the runner with memory and process churn. Use `drift_terragrunt_parallelism` to cap how many modules Terragrunt loads at once during each drift run — this is the `digger.yml` equivalent of `terragrunt run-all plan -parallelism=N`.

It can be set at three scopes; the most specific wins:

- **Project** (under a `projects:` entry): overrides everything for that one project.
- **Block** (inside a `generate_projects.blocks[]` entry): applies to every project generated by that block.
- **Top-level** (directly under `generate_projects:`): applies to every project that does not set its own value.

```yaml
generate_projects:
  drift_terragrunt_parallelism: 10   # default for every project below
  blocks:
    - block_name: prod
      include: "live/prod/**"
      terragrunt: true
      drift_terragrunt_parallelism: 20   # override for this block
    - block_name: staging
      include: "live/staging/**"
      terragrunt: true
                                          # inherits the top-level 10
```

When set, Digger appends `-parallelism=N` to every Terragrunt invocation (init, plan, apply, destroy) **during drift detection only** — `digger plan` and `digger apply` runs are unaffected. Valid values are `1` through `20`. Leave it unset to use Terragrunt's default.

## Notes

- `drift_include_patterns` / `drift_exclude_patterns` use [doublestar](https://github.com/bmatcuk/doublestar) glob matching against the project directory path.
- Per-block patterns apply only to projects generated by that block. Explicit `projects:` entries and projects from other blocks are unaffected.
- Top-level patterns under `generate_projects` apply to every generated project. When both are set, a project must satisfy each independently.
- All fields default to `[]`. If the include list is empty, every project passes the include step.
